   Why sequential models are not enough
     ➢ Real-world adversaries do not always follow a clean linear path.
     ➢ They often:
            •     pivot between hosts,
            •     repeat steps
            •     retry failed actions,
            •     reuse the same technique in different contexts,
            •     combine human and technical actions opportunistically.
     ➢ A defender may therefore observe:
             •    credential theft before obvious malware installation,
             •    lateral movement without a clear exploit phase,
             •    persistence re-established after containment,
             •    multiple techniques serving the same tactical goal.
     ➢ So if defense is to be measurable, it must be expressed in terms of observable
          behavior, not only in terms of phases.

   What MITRE ATT&CK is - and what it is not
     ➢ MITRE ATT&CK is a curated, continuously updated knowledge base of real-
       world adversary behavior.
     ➢ It is built from documented observations of intrusion campaigns and
       operational tradecraft.
     ➢ ATT&CK does not primarily catalog:
         •   malware families,
         •   vulnerabilities,
         •   specific tools.
     ➢ Instead, it catalogs behavioral patterns used by adversaries.
     ➢ ATT&CK organizes that behavior at three levels:
         ➢ Tactics = why the action is performed
            ➢     Techniques = how the objective is achieved
            ➢     Procedures = how a technique is concretely implemented in a specific campaign

ATT&CK is not another Kill Chain
ATT&CK is not a fixed attack sequence.
It does not say: first do A, then do B, then do C.
Instead, it provides a behavioral space:
• multiple techniques can support the same tactic;
• the same technique can appear in very different campaigns;
• attackers can move through the matrix in many different ways.
Example: for Credential Access, an adversary might use:
•   brute force
•   Phishing
•   credential dumping
•   password store access
•   adversary-in-the-middle
Same objective, different behaviors.

   How to read the ATT&CK matrix
     1. Columns = Tactics

          This represent adversary objectives
     2. Cells = Techniques

          These are general behavioral methods used to achieve those objectives
     3. Sub-techniques = finer-grained operational variants

       These make analysis more specific and more useful for detection.
     ➢ Read columns as goals. Select techniques based on observed behavior.

     Important:
     ➢ ATT&CK is not read left-to-right as a mandatory sequence.
     ➢ Analysts select techniques based on observed behavior, not on abstract
       campaign phases.

   The ATT&CK as a behavioral search space
     ➢ The ATT&CK matrix can be interpreted as a multidimensional space of
       adversary behavior.
     ➢ This means:
            •     an attack can be modeled as a path through tactics and techniques;
            •     different adversaries may follow different paths toward similar objectives;
            •     different campaigns may overlap behaviorally without being the same campaign.
     ➢ Therefore: behavioral overlap is informative, but it is not enough by itself for
          attribution.

   Tactics: adversary objectives
     ➢ Tactics represent the adversary’s immediate objective at a given point, such
       as:
     • Initial Access
     • Persistence
     • Privilege Escalation
     • Lateral Movement
     • Command and Control
     • Impact
     ➢ They describe why a behavior is being performed.

     Important:
     ➢ tactics are not a strict chronology;
     ➢ the same tactic may recur more than once in an operation;
     ➢ different techniques may support the same tactic.

   Techniques: reusable methods of adversary
   behavior
     ➢ Techniques describe how adversaries achieve tactical objectives.
     ➢ A good ATT&CK technique is:
     •    observable,
     •    reusable across campaigns,
     •    not tied to one specific malware family,
     •    mappable to telemetry and defensive controls.

     ➢    That is why techniques are useful for:
     •    detection engineering,
     •    coverage analysis,
     •    threat-informed defense.

     Technique: OS Credential Dumping
     May appear in very different campaigns, regardless of malware family.

A.Y. 2025 - 2026
   Procedures: campaign-specific implementations

     A procedure is the concrete implementation of a technique used in
     a specific attack campaign.
     Examples
     ➢ Enterprise IT:
     • Tactic: Credential Access
     • Technique: OS Credential Dumping
     • Procedure: Dump LSASS (Local Security Authority Subsystem Service)
       memory using a specific tool
     ➢ Industrial Control System (ICS) Context:
     • Tactic: Initial Access
     • Technique: Replication Through Removable Media
     • Procedure: Infected USB introduced into an engineering workstation in an air-
       gapped environment

   A technique is defensible only if it is observable

     ➢ A behavioral technique becomes defensible only if:
     • it leaves artifacts
     • those artifacts generate telemetry
     • the telemetry can be modeled analytically
     • the model can support detection and response
     ➢ So the defensive chain is:

         Technique ⟶ Artifact ⟶ Telemetry ⟶ Detection Logic ⟶ Response
     ➢    Example:
     •    Technique: OS Credential Dumping
     •    Artifact: abnormal access to LSASS memory
     •    Telemetry: endpoint process monitoring
     •    Detection logic: suspicious non-system process reading LSASS
     •    Response: isolate host, acquire forensic evidence

   Artifacts and telemetry
     ➢ An artifact is a trace left by an action:
     • process creation,
     • registry modification,
     • file change,
     • network connection,
     • authentication event,
     • configuration change.
     ➢ Telemetry is the mechanism that captures that trace:
     • operating system logs,
     • endpoint sensors,
     • network monitoring,
     • application logs,
     • industrial monitoring data.

   Detection is analytical interpretation
     Detection is not mere logging. Detection requires:
     • a behavioral hypothesis,
     • a baseline of normal activity,
     • collection of relevant telemetry,
     • correlation across data sources,
     • reduction of false positives,
     • prioritization of operationally meaningful alerts.


     So detection logic answers:
     “Given this telemetry, is there enough evidence to infer the presence of a technique?”

   Defensive mapping as an analytical workflow

     Defensive mapping consists of four analytical steps:
     1. Select relevant techniques
        Which ATT&CK techniques matter for our threat model?
     2. Assess visibility
        What telemetry do we collect that could reveal those techniques?
     3. Assess detection capability
        Do we actually detect them reliably and with acceptable false
        positives?
     4. Assess mitigation and residual risk
        If detection fails or arrives late, what controls still limit damage?
     ⟹ ATT&CK becomes operational only when it is connected to
     telemetry and control decisions.
Cybersecurity and National Defense (Grandi Sfide - Digital)
                                                                                26
A.Y. 2025 - 2026
   Coverage is not one thing
     ➢ Coverage must be evaluated along three dimensions:
     1.     Visibility coverage
            Do we collect telemetry relevant to the technique?
     2.     Detection coverage
            Do we identify the technique with sufficient reliability?
     3.     Mitigation coverage
            If the technique succeeds, do we have controls that reduce impact?


     ⟹ Coverage is therefore not binary. It is a layered measurement of defensive
     posture.

   Detection alone does not eliminate risk
     ➢ A technique may be:
     •    visible but not detected
     •    detected but too late to matter
     •    detected but not mitigated
     •    mitigated but still partially exploitable

     ➢ Therefore, defensive maturity requires explicit recognition of:
     •    detection limits,
     •    response latency,
     •    remaining exposure,
     •    residual risk.

   Residual Risk ATT&CK-based defense
     Residual risk is the portion of adversary behavior that remains
     unobserved, undetected, insufficiently mitigated, or still
     operationally damaging despite controls.

     In ATT&CK-based reasoning, residual risk often arises from:
     ➢ telemetry blind spots,
     ➢ weak analytical coverage,
     ➢ delayed response,
     ➢ incomplete mitigation,
     ➢ attacker adaptation.

   Behavioral models and security properties
     Each ATT&CK technique ultimately threatens one or more security
     properties:
     ➢ Confidentiality
       Example: credential dumping, collection, exfiltration
     ➢ Integrity
       Example: controller logic modification, data manipulation
     ➢ Availability
       Example: data destruction, service interruption, sabotage
     ➢ Authenticity / Trustworthiness
       Example: masquerading, malicious commands executed,
       deceptive reporting

  Stuxnet: a landmark cyber-physical operation
    ➢ Discovered in 2010, Stuxnet is the first widely recognized cyber operation that
      caused physical sabotage of industrial equipment through software
      manipulation.
    ➢ It targeted uranium enrichment centrifuges by manipulating Programmable
      Logic Controller (PLC) logic.
    ➢ Stuxnet is not just malware. It is a model case of integrated IT + OT + physical
      effects, with consequences at a strategic/geopolitical level




Cybersecurity and National Defense (Grandi Sfide - Digital)

A.Y. 2025 - 2026
  Stuxnet in one minute: what happened

    ➢ Natanz was Iran’s primary uranium-enrichment complex, built around
      cascades of gas centrifuges used to enrich uranium. Parts of the enrichment
      infrastructure were underground and heavily physical protected.
    ➢ A facility like Natanz was expected to be difficult to reach remotely, so the
      operational environment relied heavily on segmentation and air-gapping to
      reduce exposure
              ➢    weak or absent security measures were applied within the environment, most of
                   the plant's protection was relied on physical isolation.
    ➢ But Stuxnet’s designers planned for exactly that constraint: the malware was
         built to spread through infected removable media and then propagate locally
         once inside the environment, counting on the weakness of the cyber defenses
         once they managed to get inside.


Cybersecurity and National Defense (Grandi Sfide - Digital)

A.Y. 2025 - 2026
Stuxnet in one minute: what happened
➢ The best-supported public reconstruction is that Stuxnet entered the restricted
  environment through human-carried removable media, most plausibly via a maintenance
  engineer sent by Siemens to update the systems, with legitimate access in the
  environment.
➢ Once inside, Stuxnet used multiple Windows zero-days (i.e., unknown) vulnerabilities,
  propagated across local systems, checked for specific Siemens Step7 and PLC
  conditions, and activated its payload only when the target matched the intended industrial
  configuration.
➢ Once the right environment was found, it modified PLC logic related to centrifuge
  operation.
➢ The malicious logic changed operating behavior in ways
  designed to place stress on the equipment rather than cause
  an immediate obvious failure.
➢ At the same time, Stuxnet replayed or presented misleading
  normal readings to operators, masking the abnormal process
  behavior.

  Why Stuxnet matters strategically
    Stuxnet matters because it demonstrates that cyber operations can combine:
    • highly targeted intrusion
    • deep ICS / process knowledge
    • tailored payload engineering
    • stealth and deception
    • physical sabotage
    It is also historically important because it showed that:
    • air-gapped environments are not immune,
    • IT compromise can become OT manipulation,
    • software can produce strategic physical effects,
    • cyber operations can support national strategic objectives.

   What this case teaches
    Stuxnet teaches five enduring lessons:
    1. Air-gapping reduces exposure but does not remove attack
       paths.

    2. IT and OT security cannot be separated in modern industrial
       defense.

    3. If telemetry is incomplete, visibility is structurally weak.

    4. Behavioral monitoring is essential in industrial environments.

    5. Cyber operations can produce strategic physical effects.
