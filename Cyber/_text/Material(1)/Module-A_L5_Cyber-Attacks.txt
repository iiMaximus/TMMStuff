  Attack objectives
  Attacks aim to:

    ➢    Steal: data (personal / corporate / diplomatic or military), money,
         intellectual property, identity, credentials and privileged roles
         inside a system

    ➢    Damage / Disrupt: services, operations, critical infrastructures,
         logistics, healthcare, public administration, defense-related
         systems

    ➢    Manipulate / Control in a malicious way: alter decisions, falsify
         data, change system behavior, or control physical processes

  Weakness ex.: Improper Input Validation
    ➢ Improper input validation is a general class of
      design/implementation mistake. It does not yet describe a specific
      attack in a specific system.
    ➢ The system does not properly check or sanitize data received from
      users or external systems before processing it.
    ➢ Imagine a login form where the application expects a username made
      only of letters and numbers.
    ➢ If the program does not validate the input, an attacker could insert
      something unexpected, for example: ' OR '1'=‘1 instead of a normal
      username
    ➢ If the system processes that input directly in a database query, it may
      lead to SQL injection, allowing the attacker to bypass authentication.
Cybersecurity and National Defense (Grandi Sfide - Digital)
                                                                           12
A.Y. 2025 - 2026
  Weakness ex.: Hard-coded Password
    ➢ A password or secret is written directly inside the program’s code
      instead of being securely stored or configured.
    ➢ Imagine a program that contains something like:

                      if (admin_password == "admin123") {
                           grantAccess();
                      }

    ➢ If someone obtains the software or looks at the code, they may
      discover that the password is literally written inside the program.
    ➢ The problem is structural: the system design assumes that the secret
      will remain hidden, even though the software might be inspected,
      reverse-engineered, or leaked.

  Vulnerability ex.: Heartbleed
    ➢ Component involved: OpenSSL
    ➢ Publicly disclosed: April 7, 2014
    ➢ Heartbleed was a vulnerability in a widely used cryptographic
      library used to secure HTTPS connections.
    ➢ Mechanism (Heartbeat) designed to keep a secure connection
      alive:
      Client sends data + declared length → server echoes it back
    ➢ Bug: server did not verify actual message size
    ➢ Impact: server returns extra memory contents
    ➢ Leaked data may include: passwords, session cookies, private
      cryptographic keys, user data stored in memory
Cybersecurity and National Defense (Grandi Sfide - Digital)
                                                                  16
A.Y. 2025 - 2026
  Vulnerability ex.: Log4Shell
    ➢ Component involved: Apache Log4j
    ➢ Publicly disclosed: December 9, 2021
    ➢ Log4j is a library used by many applications to record log
      messages.
    ➢ Log4j supported a feature called lookup substitution, where special
      expressions inside log messages could automatically retrieve
      information from external services
    ➢ The vulnerability allowed an attacker to insert a specially crafted
      string into data that the system logs.
    ➢ When the system wrote that string into the log, the library could be
      tricked into contacting an attacker-controlled server, downloading
      and executing malicious code.

  Vulnerability ex.: EternalBlue
    ➢  Component involved: Microsoft Windows
   ➢ Publicly disclosed: April 14, 2017
   ➢ This vulnerability affected the Windows file-sharing protocol (SMB).
   ➢ In some versions of Windows, the system did not correctly validate certain
       fields in the network packets.
            • Specially crafted packets could therefore trigger a memory

                 region
   ➢ By sending specially crafted network packets to a vulnerable computer, an
       attacker could exploit the memory corruption to inject and execute code
       on the target machine, without needing an account or password.
   ➢ It was famously used by the WannaCry ransomware to spread and infect
       approximately 200,000 – 300,000 computers across more than 150

  Vulnerability
    ➢ A vulnerability is such if and only if it is exploitable.
    ➢ Exploitability depends on context
              • Reachability: Internet-facing / internal / isolated / reachable only
                through attack chains
              • Privileges & Preconditions: authentication required? local access?
                existing foothold?
              • User Interaction: victim must click / open file / enable macro / plug
                device
              • Environmental Mitigations: MFA, segmentation, sandboxing, Endpoint
                Detection and Response (EDR), memory protections, filtering
              • Operational Context: isolated lab system vs Internet-facing production
                service
    ➢ CVE present ⇏ necessarily exploitable in your environment

  Exploit
    ➢    The mean or method of taking advantage of a vulnerability for
         malicious purposes.

    How to interpret an exploit
    ➢ Technical artifact: code, payload, or crafted input that triggers a
      vulnerability (e.g., malicious document, crafted network packet)
    ➢ Operational technique: the practical way an attacker leverages
      a vulnerability in a real scenario
    Examples
    ➢ Malicious document exploiting a parser flaw
    ➢ Crafted network packet triggering remote code execution

  How cyberattacks are performed
    ➢    Cyberattacks often follow a structured process known as the
         Cyber Kill Chain, a concept borrowed from military doctrine and
         adapted to cybersecurity to describe the stages of a malicious
         operation.

    From exposure to execution
    ➢ Threat Chain → explains why systems become attackable
      (weakness → vulnerability → exploitation → attack)
    ➢ Cyber Kill Chain → explains how attacks are executed
      (how an attacker progresses from preparation to impact)

  Reconnaissance
    ➢    Goal: gather information about the target
              •    Technical information: exposed services and hosts, software versions and
                   vulnerabilities, network ranges and authentication mechanisms
              •    Organizational / human information: employee identities and email
                   formats, suppliers and partners, public documents and operational details
    ➢    Techniques:
              • Passive reconnaissance: websites, social media, public repositories,
                domain registration data, leaked credentials
              • Active reconnaissance: network scanning and host discovery, service
                   enumeration and banner grabbing
    ➢    Output:
              • Candidate entry points
              • Hypotheses about attack paths

A.Y. 2025 - 2026
  Reconnaissance — Example
    Scenario: Targeting a technology company to steal product
    designs.
    Passive reconnaissance Collect publicly available information:
    • IoT company website → departments and employees
    • LinkedIn / GitHub → engineers and technologies used
    • Job postings → infrastructure, development tools, used operating systems
    • DNS records → email format and subdomains
    Active reconnaissance
    • Scan internet-facing systems
    • Identify web apps and Virtual Private Network (VPN) portals
    • Service enumeration / banner grabbing
    Output
    Chosen entry point: spear-phishing email targeting an engineer

  Weaponization
    ➢ Goal: Prepare the malicious payload that will be delivered to
      the victim.
    ➢ Techniques:
         • Develop or adapt malware or malicious scripts
         • Create phishing pages or malicious documents
         • Reuse existing malware kits or exploit tools
         • Tailor the payload to the specific target environment

    ➢    Output:
           • A weaponized artifact ready for delivery (e.g., malicious
             document, link, or executable)

  Delivery

    ➢ Techniques: this can occur through various methods:

  Exploitation
    ➢ Goal: The delivered malware exploits a vulnerability or user

    ➢ Techniques:
    •    Exploit software vulnerabilities (e.g., memory corruption, browser flaws)

  Installation
    ➢ Goal: the attacker establishes a persistent presence on the
      targeted system, often installing a backdoor to allow continuous
      access.
    ➢ Techniques:
    • Install malware or backdoor for remote access
    • Download additional malicious components
    • Create persistence mechanisms (startup tasks, services)
    • Hide activity using obfuscation or privilege abuse
    ➢ Output:
    • Persistent access to the compromised system
    • Platform for surveillance, lateral movement, or data theft

  Command and Control (C2)
    ➢    Goal: allow the attacker to remotely control the compromised
         system.
    ➢    Techniques:
    •    Malware establishes connection to attacker-controlled server
    •    Periodic beaconing to receive instructions
    •    Integration into botnets or coordinated infrastructures
    ➢    Output:
    •    Compromised host becomes a remotely managed asset
    •    Attacker can issue commands, update malware, and exfiltrate
         data

  Actions on Objectives
    ➢ Goal: The attacker takes actions to achieve their ultimate
      objectives, whether it’s data exfiltration, system damage, creating
      a botnet, or any other malicious outcome.
    ➢ Techniques:
    •    Data exfiltration (documents, credentials, intellectual property)
    •    System manipulation or sabotage
    •    Fraud or extortion (e.g., ransomware)
    •    Infrastructure abuse (botnets, staging points)
    ➢    Output:
    •    Confidentiality breach (data theft)
    •    Integrity compromise (data manipulation)
    •    Availability disruption (service interruption)

  Where can defenders break the chain?
    1. Reconnaissance ⟶ (Detect) exposure management, deception,
          monitoring
    2. Weaponization ⟶ (Prevent / Detect) threat intelligence, attack surface
          reduction, sandboxing/detonation
    3.    Delivery ⟶ (Prevent) filtering, email/web security, user training
    4.    Exploitation ⟶ (Prevent / Detect) patching, hardening, monitoring
    5.    Installation ⟶ (Prevent / Detect) application control, least privilege,
          monitoring
    6.    C2 ⟶ (Prevent / Detect) network detection, egress control (i.e., monitor and
          restrict outgoing network traffic from an internal system or network to the
          outside world)
    7.    Actions on Objectives ⟶ (Respond) incident response, containment,
          eradication, recovery

  Kill Chain: useful, but not universal
    ➢ Effective for many intrusion-oriented campaigns
    ➢ Less suitable for all attack types and all adversarial behaviours
    ➢ Other models answer different questions:
              •    Attack trees ⟶ how can a goal be achieved?
                   o   We start from an attacker objective and decompose it into alternative ways to
                       achieve that objective
              •    Attack graphs ⟶ what paths can an attacker follow through a system or
                   network?
                   o   Useful when we want to understand the possible paths an attacker can follow
                       through a system or a network
              •    Attack nets ⟶ how does an attack progress through different states or
                   conditions?
                    o Represent how an attack progresses through different states or conditions
                       in a system
    ➢    Good analysts use the model as a tool, not as a rigid template

    General legal definition
    Cybercrime refers to criminal offences that are committed using
    computer systems, networks, or digital data, or that target
    computer systems and data themselves.
    Two broad categories

    ➢    Cyber-dependent crimes: crime that exists only because digital
         systems exist
              • Examples: malware, ransomware, botnets, DDoS-for-hire

  Cyberspace: no man's land…
    ➢    Cyberspace is often considered “no man's land” because of:
          • Absence of clear boundaries: a digital operation can move through
            devices, networks, cloud services, registrars, hosting providers, and
            communication channels distributed across many countries ⇒ the “location”
            of an attack is often ambiguous.
          • Lack of clear transnational jurisdiction: a victim may be in one country,
            the attacker in another, the infrastructure in a third, and the financial flows
            in several others. This complicates attribution, evidence gathering, and legal
            cooperation.
          • Social paradigms are radically different: the Internet removes the need
            for physical proximity, reduces the cost of reaching victims, accelerates
            operations, and makes large-scale targeting feasible in ways that were
            much harder in the physical world.

  Consequences: economic asymmetry and
  Crime-as-a-Service
    ➢ Attack infrastructure has fixed costs: tooling, malware,

    ➢ Defenders face the opposite logic: each asset, control, or

      outsourced
    ➢ Result: attacks scale with less effort, lower expertise, and
