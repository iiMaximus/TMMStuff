   Introduction
    ➢ what is an operating system (OS)?​
    ➢ an organized collection of software extensions of hardware that
      serve as:
         ➢ control routines for operating a computer (for example, to

           gain access to computer resources (like file I/O))
         ➢ an environment for execution of programs

         ➢ an OS is an interface between the end user and the

           hardware

   Software Execution (I)
    ➢      instructions reside in main memory (RAM)
    ➢      the CPU fetches each instruction and execute it
    ➢      instructions (aka software) need to be moved from persistent
           storage (e.g., HDD, SSD) to main memory
    ➢      on simple devices that execute only one application (e.g., IoT),
           only the executed application needs to be loaded in RAM
    ➢      when the device starts, a special component called bootloader
           moves the application in RAM where the CPU will be able to
           fetch the instructions and execute them

   Software Execution (II)
    ➢      on general purpose machines, the OS substitute the bootloader
           for user applications
    ➢      the OS runs at a higher privileged level, in order to load
           applications in RAM and allocate the main memory when
           requested
    ➢      this hides several specific hardware aspects to developers and
           users

   Operating System Services (I)
    ➢ the OS provide an execution environment for executing
      programs and services
    ➢ the main services provided are:
         ➢ user interface: it can be based on Command-Line (CLI),

           Graphics User Interface (GUI)
         ➢ program execution: the OS load a program in the main

           memory and run it, handling errors during execution
         ➢ I/O operations: it manages the input/output from storage

           devices
         ➢ filesystem manipulation: it manages the creation and

           manipulation of files, in particular managing permissions

   System Calls
    ➢ programming interface provided by the OS to access its services
    ➢ typically written in an high-level language (C, C++, Rust)
    ➢ they are mainly accessed by programs through higher level
      Application Programming Interface (API)
    ➢ several API standards:
         ➢ Win32 for Windows

         ➢ POSIX for POSIX-based systems (Linux, macOS, Solaris)

         ➢ Java API for the Java Virtual Machine (JVM)

      returns the results
    ➢ the caller (user) does not need to know how the system calls are
      implemented, it just needs to follow the API rules

   Example – Standard C Library (I)
    ➢ in UNIX and Linux systems, the standard C library acts as a
      bridge between user applications and the operating system's
      kernel
    ➢ rather than requiring programs to communicate with the
      hardware directly, the library handles the complexities of the
      system-call interface.

   Example – Standard C Library (II)
    ➢    for example, when a C program executes a printf()
         statement:
            ➢ the C library catches this request.

            ➢ it translates the request into the appropriate system-level

               command, such as the write() system call.
            ➢ the kernel processes the request and returns a result to the

               library.
            ➢ the library then relays that return value back to the original

               user program.

   Policy vs Mechanism (I)
    ➢ OS abstracts implementation details
    ➢ user can describe the desired behavior
    ➢ policy: represents what needs to be done
    ➢ mechanism: represents how something needs to be done
    ➢ the mechanism is transparent to the policy




Cybersecurity and National Defence (Grandi Sfide - Digital)
                                                              33
A.Y. 2025 - 2026
   Policy vs Mechanism (II)
    ➢ typically the user does not want to implement, for example
      security, but wants to “state” what has to be behavior of the
      system
    ➢ the user defines its policy, defining a set of rules that the system
      needs to follow in order to enforce the user requirements
    ➢ the system is in charge of following the rules (policy) and
      implement the mechanism to follow them
    ➢ there can be different implementation the enforce the same rule
