Randomness and pseudo randomness
• true random numbers and sequences
  • generated with random processes
     • physical processes: white noise, Brownian processes, ...
• pseudo-random numbers and pseudo-random sequences
  • generated with a deterministic process
  • …statistically indistinguishable from true random numbers/sequences
     • require sources of entropy to start
     • if the processes are weak, sequences are predictable
  • pseudo-random generators can only generate a finite number of sequences
     • imagine them numbered  associated them with an integer number
         • this integer is named seed

Why do we need randomness?
• processes: select a random number and keep it secret
   • e.g. a cryptographic key

   • so attackers cannot gain any knowledge from it

 • principle that states that something is

Cryptography strenght
(Kerckhoffs principle)
  • if the keys:
      • are kept secret
      • are managed only by trusted systems
      • are of adequate length
  • then ...
  • ... it has no importance that the encryption and decryption algorithms are
    kept secret
  • ... on the contrary, it is better to make the algorithms public so that they
    can be widely analysed and their possible weaknesses identified

  Auguste Kerckhoffs, "La cryptographie militaire", Journal des sciences militaires,
  vol. IX, pp. 5–38, Janvier 1883, pp. 161–191, Février 1883.

Algorithms become obsolete
• time to guess keys reduces by evolution of the technology
   • algorithms will sooner or lated become weak
      • computers can perform many more trials in the same amount of time
      • brute force can be easily parallelized
          • e.g., GPUs with hunderd cores
   • DES used a 56-bit key and is definitely obsolete
• cryptanalysis
   • theoretical and statistical techniques that, based on observations, reduce
     the search space
      • DES: 56 →~40bit

Algoritmi simmetrici di tipo stream
 • operate on a stream of data without requiring the division in blocks,
   typically on one bit or one byte at a time
 • ideal algorithm
    • one-time pad (requires a key which is as long as the message to protect!)
 • real algorithms
    • pseudo-random generators where the key is used as a seed
       • every time I use the same seed, the algorithm generates the same sequence
    • bitwise XOR between the plaintext and the sequence
       • (old) RC4, SEAL
       • (modern ma not state of the art) Salsa20
       • (state of the art) ChaCha20

Integrity check: high-level approach
 • the sender uses a function to generate evidence of how data are
   made when he/she was sure they were correct
    • e.g. before sending both, data and evidence
 • the recipient uses the same function on the data in his possession
    • e.g. the just received ones
 • compare
    • if the function returns the same value (sender-side and recipient-side)
       • received data are correct
    • otherwise, they don’t satisfy the integrity principle
 • how to perform the comparison?
    • using secure algorithms and sharing the evidence in secure ways!
                  Message digest and hash functions
                  • the message digest is a fixed-length “summary” of the message to
                    be protected (of any length)
                  • it must be
                     • fast to compute
                     • impossible or very difficult to invert
                     • difficult to create “collisions”
                  • digest often used to avoid performing operations on the whole
                    message, especially when the message is very large
                     • e.g. because public-key cryptography is very slow
                  • digest can be calculated in many ways, but usually via a
                    (cryptographic) hash function

Lunghezza del digest
• if the algorithm is well-designed
   • then all digests are pseudo-random
• if I change one bit of the input message
   • on average, 50% of the bits in the digest change
• it is always possible to generate messages with the same digest
   • If the algorithm generates an n-bit digest, then:
       • to find a message that has the same digest as a fixed message, 2ⁿ attempts are needed
       • to find two messages with the same digest, 2^(n/2) attempts are needed
• digests with many bits are required to make collisions statistically negligible
   • said to have n bits of security if on average 2ⁿ attempts are needed to carry out the easiest
     attack
• a hash function is considered valid if it has a security strength of at least 80 bits

                  • define the SHA-2 family (based on the same math as SHA-1):
                     • SHA-2 = {SHA-224, SHA-256, SHA-354, SHA-512}
                     • SHA-256 larger block = 32 bit
                     • SHA-512 larger block = 64 bit
                     • SHA-224/-354 = troncamento di SHA-256/-512
                  • SHA-3 selected through a competition
                     • completely new scheme
                     • winner Keccak (“catch-ack”)
                     • the best one available nowadays

Authentication based on knowledge
• prove that you are a specific user
   • by demonstrating that you know a secret that only you can know
   • or you share with other people/users involved in the authentication
• in cryptography, keys are kept secret
   • so can be used for data authentication
• a digest can also work
   • calculated not only on the data but also on a secret (key)
      • called a keyed digest or Message Authentication Code (MAC)

                  Keyed-digest: HMAC
                  • RFC-2104 (also FIPS-198)
                  • base hash function H:
                    • B byte block, L byte output, with B > L
                  • definitions:
                     • ipad = 0x36 repeated B times
                     • opad = 0x5C repeated B times
                     • deprecated keys s.t. | K | < L
                     • if | K | > B then K' = H ( K ) else K' = K
                     • if | K' | < B then K' is 0-padded up to B bytes
                  • hmac = H( K' ⊕ opad || H( K' ⊕ ipad || data ) )

                  Authenticated Encryption (AE)
                  • one single operation for privacy and authentication (and integrity):
                     • just one key and one algorithm
                     • better speed
                     • less error likelihood in combining the two functions
                  • needed by applications (e.g. e-mail messages, network packets)
                  • GCM the most used one
                     • used by TLS
                     • during the encryption
                        • generates ciphertext + authentication tag
                     • fast on present CPUs
