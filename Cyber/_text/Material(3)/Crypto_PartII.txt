                       • asymmetric algoritms (aka public key algorithms)
                          • two distinct keys
                              • for the two operations encrypt/decrypt
                          • encryption/decryption algorithms may also be different
                              • but they may also be very different
                       • computationally heavy
                          • cannot be used to encrypt large quantity of data
                          • good for distributing a few bytes

                          • good for digital signatures
                              • if combined with hash functions
                       • main (classical) algorithms are
                          • Diffie-Hellman, RSA, DSA, El Gamal, ECDSA…

Asymmetric keys
• keys are generated in pairs
   • they must have inverse functionalities
       • encryption operations made with one key, must be annihilated when the other key (of the pair) is
         used
   • cannot be simply random
       • must share some mathematical properties
• semantics of asymmetric keys
   • one key is kept secret
       • hence, it becomes the private key
   • one is distributed to everyone
       • hence becomes the public key
       • no confidentiality issues must affect this second one
   • in some cryptosystems, public and private keys are indistinguishable
       • e.g., RSA
       • public vs. private is just a matter of choice
       • in some cryptosystems, they are different

Public key algorithms
 • RSA (Rivest - Shamir - Adleman)
    • product of prime numbers
       • inverse: factoring of the result
    • finite fields (modulo n)
    • secrecy and digital signature

 • DSA (Digital Signature Algorithm)
    • compute the power
       • inverse: logarithm of the result
    • only for digital signatures
       • for encryption, combine it with El-Gamal
RSA – the algorithm (I)
 • generation
    • public module n = p q known to anybody
       • p and q are prime, large, and secret
    • PHI = (p-1) (q-1)
    • choose a number (public exponent) e such that arbitrarily 1 < e < PHI and it
      is relatively prime with respect to PHI
    • compute the (private exponent) d = e-1 mod PHI
       • if an attacker comes to know p and q, then he can compute d
       • you can also compute d from n and e
 • public key = (n, e)
 • private key = (n, d)
RSA – the algorithm (II)
 • RSA may cipher/decipher only data whose value is less than the
   value of the module n
    • plaintext:     P<n
    • encrypt:       C = Pe mod n
    • decrypt:       P = Cd mod n
 • the roles of e and d are interchangeable because
    (Pd)e mod N = (Pe)d mod n
    • the complexity of the operations depends upon the number of bits with
      value 1 in the exponents e and d
Hard cryptographic problems
• RSA PROBLEM
   • given (n,e) public  compute d


• factorization PROBLEM
   • given (n,e) compute first p e q s.t. n=pq
   • having factored n, compute d

• factorization is the hardest problem
   • even if you know e and d you cannot factor n

3. Data authentication with asymmetric
crypto
 • compute a digest of the data to authenticate, encrypted with the
   private key of the originator
    • (signer S)       H = enc( S_Kpri, hash( M ) )
    • (send)           M || H
    • (verifier V)     X = dec( S_Kpub, H )
    • (verification)   if ( X == hash( M ) ) then OK else ALARM!
 • who knows the public key of the originator can extract the digest
   and compare it with the one computed on the received data
 • DIGITAL SIGNATURE (the «real» one)
    • also need to manage padding to avoid attacks

Elliptic curve cryptography
 • ECC (Elliptic Curve Cryptosystem)
    • instead of using modular arithmetic, operations are executed on a 2D
      (elliptic) curve
 • problems as complex as the ones on modular arithmetic
    • every operation attackers have to do is more computationally demanding
       • use shorter keys (~ 1/10)
       • much faster for legitimate users
 • applications
    • digital signatures = ECDSA
    • key agreement = ECDH

2. KDF (Key Derivation Function)
 • symmetric keys must be random
 • … users prefer passwords (or passphrases)
    • simple and predictable, not really random in the best case
 • K = KDF ( P, S, iterations )
    • P = password or passphrase
    • S = salt (make K less predicatable)
    • iterations = n. of times the same function is executed
        • slow down attackers when performing brute force attacks
        • iterations = 4096 (Kerberos, 2005), 2000 (iOS3), 10000 (iOS4), 5000 (LastPass JS client,
          2011), 100000 (LastPass server)
 • KDF originally based crpto hashes
    • PBKDF2 (RFC-2898) uses SHA-1, |S| ≥ 64, itc ≥ 1000
    • HKDF (RFC-5869) uses HMAC
DH, RSA and quantum computers
• DH ~ solve the discrete logarithm
   • if A = gX mod p then x = logg A mod p
   • multiplications ~ number of trials multiple of p
      • exponentially grows with the number of bits of p
   • more efficient algorithms exist (e.g. Pohlig–Hellman, number field
     sieve)
      • all are exponential, though
   • if you can solve the discrete logarithm polynomially, you can also factorise
     numbers polynomially starting from those results, and vice versa
• however… the Shor’s algorithm appeared...
L’algoritmo di Shor
 • proposed by Pete Shor to factorize integers
 • very fast on ... quantum computers
    • logarithmic complexity
       • N (~ O((log N)3) )
 • still, quantum computers able to execute Shor’s algorithm on non-
   trivial numbers are not available (yet)
    • fes bits, a lot of bits needed to perform error correction
       • (2012) a 7 qubit computer solved 21 = 3 x 7
       • (2014) adiabatic quantum computation fattored 56153 = 233 x 241
       • (2023) IBM Osprey, 443 quantum bit
 • RSA, DSA, and ECC versions would become weak immediately weak
    • harvest now, decrypt later...

   • Lattice-based cryptography
   • Multivariate cryptography
   • Hash-based cryptography
   • Code-based cryptography
